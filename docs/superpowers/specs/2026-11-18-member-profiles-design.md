# Профили участников: клиент V1

Дата: 18 ноября 2026. Статус: согласовано пользователем; дополнение — раскат по конкретным user ID.

## Цель и ограничения

Дать активным авторизованным участникам возможность делиться опытом мероприятий и находить компанию. Использовать существующие React, React Router, авторизацию, UI и платформенный openLink. Все публикации проходят ручную премодерацию. Чаты, рейтинги, изображения в рассказах и автоматическое одобрение вне V1.

Источник требований: переданный handoff и `docs/member-profiles-client.md`, `web/schemas/member_content.py`, `services/utils/member_payload.py` соседнего backend-репозитория `sber-tg-bot`. Локальный backend находится в ветке `fix/member-profile-client-state`; это не подтверждение деплоя дополнений API.

## Подходы

Выбор исполнителя: встроить экраны в существующую навигацию, выделив отдельный модуль сообщества для API, состояния и аналитики. Это позволяет использовать действующие вход, платформенные ссылки и административные права.

Отдельный раздел нижней навигации добавил бы ещё одну основную вкладку при наличии существующего профиля; для V1 достаточно входа из него. Поэтапный выпуск только профилей оставляет сценарии мероприятий и модерации незавершёнными, поэтому весь V1 готовится одним PR за выключенным флагом.

## Экраны и навигация

- Текущий `/profile` сохраняет настройки; получает вход «Профиль участника».
- `/members/me/edit`: собственная форма, черновик и отдельная отправка на проверку; состояния, причина возврата, опубликованность, скрытие и отзыв контакта.
- `/members/:userId`: опубликованные фото, имя, описание, компания, должность, интересы, контакт и два списка публикаций с переходом к событиям.
- Карточка события получает блок «Сообщество»: рекомендации, рассказы, собственные формы и поиск компании. В превью заявки этот блок отсутствует.
- Текущая модерация получает вкладку «Сообщество», доступную только администратору, включая проверку при прямом переходе.

Схема собственной формы:

```text
Профиль участника
Статус проверки · видна ли прежняя публикация · причина возврата
Имя / описание / компания / должность / интересы
Фото: без фото или явный выбор доступного связанного аккаунта
Контакт HTTPS / подпись
[Сохранить черновик]  [Отправить на проверку]
Контакт после одобрения доступен всем авторизованным участникам,
даже когда поиск компании выключен. Явное подтверждение перед отправкой.
[Скрыть профиль]  [Отозвать контакт]
```

Контакты аккаунта автоматически не подставляются. При повторном редактировании выбор фото делается явно: provider по URL не определяется. Все поля и ограничения соответствуют backend-контракту. Тексты выводятся обычным React-текстом, без HTML.

## Состояние, доступ и запросы

Отдельный SOCIAL_PROFILES_ALLOWLIST в существующей системе featureFlags: new Set([userId, ...]) для выборочного доступа, ALL_USERS для общего выпуска, по умолчанию пустой Set. Админские действия дополнительно требуют is_admin=true; включение в allowlist не даёт прав администратора. Он закрывает точки входа, маршруты и запросы; 404 не используется для определения доступности функции.

Возврат после входа принимает только разрешённый внутренний адрес профиля, сохраняет его на время существующего входа и восстанавливает после успешной авторизации. Внешние и некорректные адреса отбрасываются. При отсутствии действующей авторизации контактные данные не рендерятся. Состояние сообщества изолировано по сессии; выход, смена пользователя и 401 очищают данные и отменяют запросы. Профили и контакты не сохраняются в постоянный браузерный кэш. Асинхронное ожидание SDK в авторизации сохраняется.

Публичные и собственные снимки хранятся раздельно. Читатель никогда не получает owner payload. Списки имеют пагинацию; свои формы ищутся по `kind + event_id` с продолжением страниц до нахождения или конца списка. Переключатель компании восстанавливается исключительно отдельным GET companion-request.

Сохранение отправляет разрешённые поля полного снимка. Отправка использует generation сохранённой версии и недоступна для несохранённых правок. 202 показывается как приём на проверку. После действий перечитываются собственные состояния; при открытии, возвращении на экран и ручном обновлении статусы загружаются заново, без выдуманного push-канала.

409 перечитывает актуальную версию без автоматического повтора submit/решения. 401 запускает существующий вход; 403, 404 и 422 получают понятные сообщения. detail поддерживает строку и массив ошибок FastAPI. Незавершённые действия блокируют повторные клики. Поздние ответы прежней сессии/страницы игнорируются.

Скрытие и отзыв контакта после подтверждённого ответа немедленно очищают соответствующее состояние, перечитывают owner и поиск компании. При ошибке UI сообщает её и не изображает успешный отзыв.

## Мероприятия

Для создания рекомендаций и рассказов нужен опубликованный профиль: при его отсутствии показывать объяснение и переход к собственному профилю. Автор может отдельно убрать свою рекомендацию или рассказ через соответствующий DELETE; после подтверждённого ответа обновляются публичные списки и собственное состояние.

Новая рекомендация доступна до начала, включая вариант без текста; существующую опубликованную можно редактировать. Рассказ доступен после окончания с обязательным «Я участвовал», обозначенным как заявление автора. Временные границы вычисляются в Europe/Moscow по контракту, включая неизвестную дату и отсутствие времени. Backend остаётся окончательным источником допустимости действия.

Поиск компании требует опубликованных профиля и контакта. PUT/DELETE не меняет личную отметку «Пойду» и календари. Во время запроса переключатель заблокирован; после него перечитываются состояние и список. Ошибка не оставляет неподтверждённый результат. При наступлении времени начала и возвращении на экран состояние обновляется; отсутствие автора в странице списка не означает выключенный поиск.

## Модерация

Показывать текущую отправленную версию, user_id автора, событие, дату отправки, результат автопроверки как подсказку. При первой публикации автора 404 публичного профиля не ломает очередь: отображаются поля проверяемого профиля. Для сравнения загружать только доступный опубликованный снимок, не обещать историю версий.

Одобрение/возврат используют revision_id и generation. Причина возврата обязательна; собственное одобрение запрещено. Административное снятие опубликованной записи с причиной доступно администратору на публичном профиле/публикации. После решения очередь перечитывается с учётом изменения её состава.

## Аналитика

Передавать только разрешённые идентификаторы и source, без текстов и контактов. Исключать собственные просмотры и модерацию. Сохранять source=companions при переходах через профиль, в том числе в адресе ссылки при перезагрузке.

Рассказы открываются явным действием: experience_open подтверждается сервером до интервалов чтения. UUID сохраняется при повторе одного события. Интервалы до 15 секунд учитывают фактическую видимость открытого рассказа, вкладки и активность пользователя; после 60 секунд без действий учёт приостанавливается. Закрытие, скрытие вкладки, смена сессии и размонтирование прекращают учёт. Ошибка аналитики не блокирует чтение или открытие контакта. Повторы ограничены текущей сессией, пачки не более 50 событий.

## Проверка и выпуск

Добавить содержательные Vitest/Testing Library проверки доступа и возврата после входа, очистки и поздних ответов, разделения публичной/собственной версии, generation/409, восстановления формы с последующих страниц, независимого companion-request, временных границ, модерации и измерения чтения. Выполнить тесты, production build и lint; существующие несвязанные ошибки отметить отдельно.

Подготовить feature-ветку и отдельный frontend PR без включения функции. В PR указать backend-зависимости и результаты автоматических проверок. Совместный E2E с автором, читателем и отдельным администратором провести только при доступном согласованном стенде; зафиксировать адрес и результат перед включением. Без стенда явно оставить E2E непроверенным. Миграции не запускать, backend-флаги и лексический автовозврат не включать.

## Решения исполнителя и открытые условия

Предложены исполнителем: адреса `/members/...`, блок «Сообщество», вкладка в существующей модерации, явное открытие рассказа для измерения чтения, хранение данных только в памяти текущей сессии, выпуск полным V1 за выключенным флагом.

Ограничение текущего API: `/users/me` не возвращает перечень identities, отдельного маршрута их списка в локальных роутерах не найдено. В форме можно предлагать только подтверждённый связанный аккаунт (например, действующий платформенный вход), без определения provider по фото или догадок о других аккаунтах; при отсутствии подтверждённого источника доступен вариант «Без фото». Полный выбор всех связанных аккаунтов требует дополнения backend API. Это ограничение необходимо явно указать в форме и PR.

До включения требуется подтверждённый стенд с дополнениями API и совместный E2E.
