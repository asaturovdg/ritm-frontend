# Сообщество: раскат и проверка

Функция выключена по умолчанию. В `src/data/featureFlags.js`:

```js
// Только эти user_id из API /users/me:
export const SOCIAL_PROFILES_ALLOWLIST = new Set([123, 456]);
// Всем после совместного E2E:
// export const SOCIAL_PROFILES_ALLOWLIST = ALL_USERS;
```

Пустой `new Set()` скрывает точки входа, закрывает прямые маршруты и отключает
запросы сообщества. Администратор для модерации должен одновременно входить в
allowlist и иметь `is_admin=true`. Клиентский флаг не заменяет права backend.

Маршруты: `/members/me/edit`, `/members/:userId?source=companions`. Вход в свой
профиль — из текущего профиля настроек; в модерации — вкладка «Сообщество».

Перед раскатом требуются backend с `SOCIAL_PROFILES=true`, применённая обычным
деплой-процессом схема и дополнения API: owner `event_id` и GET companion-request.
Миграции и серверные флаги этот PR не запускает. Общий What's New не изменяется,
поскольку функция ещё закрыта для пользователей.

## Ограничения текущего контракта

- `/users/me` не содержит списка identities. Форма предлагает только подтверждённый
  связанный Telegram (`telegram_id`) или отсутствие фото. Произвольный URL и
  определение провайдера по фото не используются. Для выбора всех связанных
  Max/VK/email нужен endpoint identities от backend.
- Публичный профиль содержит `user_id`, но не ID записи profile. Снятие чужого
  профиля доступно в очереди либо в форме модерации по ID записи из очереди.
  Нельзя подставлять user_id вместо ID записи. Для прямого снятия из публичного
  профиля нужен отдельный административный lookup или ID записи в DTO.
- Неподтверждённые submit и решения после 401/409 автоматически не повторяются.
  После восстановления входа пользователь проверяет актуальную форму.
- Профили/контакты живут только в памяти сессии, без localStorage-кэша.
  В sessionStorage хранится только проверенный внутренний адрес возврата.

## E2E перед включением

Использовать автора, читателя и отдельного администратора на одном стенде:

1. Вход по ссылке профиля и возврат; выход/смена пользователя убирают контакт.
2. Черновик скрыт; submit принят на проверку; возврат показывает причину;
   approve публикует; при проверке правки читатель видит одобренный снимок.
3. Старая generation даёт 409 без повтора; формы событий восстанавливаются с
   последующих страниц собственных записей.
4. Поиск восстанавливается отдельным GET, независимо от страницы companions;
   отзыв контакта/скрытие профиля выключает его; повторная публикация не включает.
5. При начале события поиск прекращается; личная отметка «Пойду» не меняется.
6. Рекомендация может быть без текста; рассказ требует завершения и заявления
   об участии. Проверить границы суток Москвы и события без части дат/времени.
7. Обычный пользователь не получает очередь; админ не проверяет свою запись.
8. UUID не дублирует события; интервалы чтения идут после open, не идут при
   закрытом рассказе, вне viewport, в фоне, после 60 секунд без активности.

В PR зафиксировать URL стенда и результат. Локальные браузерные проверки с моками
проверяют интерфейс и не заменяют этот совместный E2E.
